# ModelStudio — BOUT DX11 리소스 뷰어

Framework 솔루션에 추가한 독립적인 C++17 / Win32 / Direct3D 11 프로그램입니다.
브라우저, Python, Blender 없이 BSC/BON과 원본 텍스처를 직접 읽어 렌더링합니다.
기존 Client/Engine 프로젝트에 링크 의존성을 추가하지 않았습니다.

## 실행

1. `Framework.sln`을 Visual Studio 2022에서 엽니다.
2. `ModelStudio`를 **시작 프로젝트로 설정**합니다.
3. **Debug 또는 Release / x64**로 빌드 후 실행합니다.

빌드된 실행 파일: `ModelStudio/bin/x64/Release/ModelStudio.exe`

필수 개발 구성 요소는 VS의 **C++를 사용한 데스크톱 개발**, v143 도구 집합, Windows SDK입니다.
셰이더는 실행 시 시스템의 D3DCompiler로 컴파일합니다. 별도 다운로드나 NuGet 의존성은 없습니다.

시작 시 Windows가 알려주는 바탕 화면의 `바우트 리소스` 폴더를 찾습니다.
다른 위치라면 왼쪽 위 **폴더…**로 `플레이어`, `monster`를 포함한 상위 폴더를 지정하세요.
원본 리소스는 읽기만 하며 프로젝트나 Git에 복사하지 않습니다.

## 플레이어 조립과 파일 교체

- 상단 목록에서 **Player / Az, Gr, Hs → 세트 열기**를 선택합니다.
- 해당 클래스의 `*_000_body.bsc`, `*_000_arm.bsc`, `*_000_head.bsc`와 `*_bone.bon`을 함께 읽습니다.
- **편집할 부위**에서 Body, Arm, Head를 선택하고 **BSC 교체…**를 누르면 그 부위만 바뀝니다.
- 메시 교체 시 같은 파일명의 BA~BD 텍스처를 자동 연결합니다. `0` 버전을 우선하고, 없으면 `2` 버전을 사용합니다.
- 아래 A/B/C/D 텍스처 슬롯은 **현재 선택한 부위**에만 적용됩니다. 슬롯별 교체·해제가 가능합니다.
- **표시**로 부위를 숨기거나, **메시 해제**로 해당 메시와 텍스처를 비웁니다.
- 다른 부위를 유지하면서 장비 변형을 교체할 수 있습니다. 본 이름은 대소문자를 구분하지 않습니다.

클래스마다 같은 본 번호의 의미가 다를 수 있습니다. Az/Gr/Hs가 명시된 파일은 클래스가 다른 BON과의 조합을 거부합니다.
Python 예제의 추정 자세 및 의미 기반 리타겟팅은 이식하지 않았습니다. **이종 클래스 장비 자동 리타겟팅은 지원하지 않습니다.**

## 몬스터

- 상단의 **Monster / 이름 → 세트 열기**로 BSC, 같은 이름의 BON, 텍스처를 함께 엽니다.
- **Monster** 슬롯에서 BSC를 직접 교체해도 같은 이름의 BON과 텍스처를 찾아 연결합니다.
- 몬스터 세트로 전환하면 플레이어 부위를 비웁니다. 플레이어 세트로 전환하면 몬스터를 비웁니다.
- BSC/BON 한 파일을 뷰포트에 끌어놓을 수도 있습니다. BSC는 선택한 슬롯에 적용됩니다.
- 분리된 메시를 직접 조합하려면 Body/Arm/Head 슬롯에 각각 넣고, 모두의 본 이름을 포함하는 BON을 지정하세요.

## 애니메이션 / 카메라

- **BON 교체…**는 모든 활성 부위가 사용하는 애니메이션을 교체합니다.
- 본 이름이 맞지 않거나 파일 구조가 잘못된 경우 오류를 표시하고 기존 모델을 유지합니다.
- **전체 모션 / 클립 번호**, **15·30·60 FPS**, **재생/정지**, **프레임 슬라이더**를 제공합니다.
- 클립 이름과 원본 재생 속도는 확인되지 않아 번호와 사용자가 선택한 FPS로 표시합니다.
- BON 행렬은 원본의 행 벡터/월드 변환을 그대로 적용합니다. 별도의 스킨 가중치 계산이 필요 없는 파츠 애니메이션입니다.
- **BON 해제**는 파츠의 로컬 좌표를 보여줍니다. 완성된 기본 자세를 추정해 만들지 않으므로 파츠가 겹칠 수 있습니다.
- 뷰포트 좌드래그: 회전 / 우드래그: 이동 / 휠: 확대 / F: 화면 맞춤 / Space: 재생·정지.
- 와이어프레임, 클레이, 바닥 그리드, 본 위치 십자 표시를 켜고 끌 수 있습니다.
- 작은 창에서는 오른쪽 스크롤바 또는 설정 영역 위의 마우스 휠로 아래 설정에 접근합니다.

## 지원 범위

- 검증된 BSC 정점 44바이트 및 16비트 인덱스 구조, BON의 본별 행렬 배열.
- PNG/JPEG/BMP 등 WIC 지원 이미지, 비압축/RLE TGA, DXT1/DXT3/DXT5 DDS.
- 확장자가 BA0/BB2 등이어도 이미지 내용으로 판별합니다.
- 재질 0~3은 A~D 텍스처를 사용하며 더 높은 재질 번호는 클레이로 표시합니다.
- 재질 1에 텍스처가 있으면 알파 블렌딩합니다. 파츠 단위로 뒤에서 앞으로 그리며, 원작의 가산광·이펙트 셰이더를 완전히 복원한 것은 아닙니다.
- 자동 텍스처 로딩 실패 시 해당 슬롯은 클레이로 표시하고 파일명을 알립니다. 수동 교체 실패 시 기존 텍스처를 유지합니다.
- 일부 변형 파일은 아직 지원하지 않습니다. 실패한 파일을 부분적으로 읽어 잘못 그리지 않도록 범위·좌표·행렬을 검증합니다.
- 이 프로젝트는 보기와 리소스 교체용입니다. 기존 웹 뷰어의 GLB/FBX 내보내기는 이 프로젝트에 포함하지 않았습니다.

## 코드 구성

| 파일 | 역할 |
|---|---|
| Assets.h / Assets.cpp | BSC/BON 파싱, 데이터 검증, 같은 이름의 리소스 탐색 |
| Renderer.h / Renderer.cpp | DX11 장치/버퍼/셰이더, 텍스처 디코딩, 카메라, 렌더링 |
| Main.cpp | Win32 UI, 슬롯 상태, 파일 교체 트랜잭션, 재생 루프 |
| Verification.cpp | 실제 DX11 WARP 렌더링과 파서/정점 위치 검증 |
| prepare-reference.cjs | 기존 JavaScript 파서로 비교용 좌표 생성 (검증에만 Node.js 사용) |

다른 게임 프로젝트에서 활용하려면 Assets와 Renderer를 분리해 가져갈 수 있습니다.
`Slot`마다 CPU 모델/GPU 버퍼/텍스처를 소유하고, `Animation` 하나를 여러 슬롯이 공유합니다.
COM 자원은 `ComPtr`로 관리합니다. 교체 대상 리소스를 먼저 만든 다음 검증에 성공했을 때만 활성 상태를 바꿉니다.

- 0/100/419/마지막 프레임의 파츠별 첫 정점 총 520개를 기존 JavaScript 파서와 비교했습니다. 최대 좌표 차이는 약 0.0000153입니다.
- 제공된 폴더 전체 검사: BSC 79개, BON 67개 통과. 변형/비정상 데이터 22개는 거부됩니다.
- UI 상태 통합 검사: 목록 검색, 플레이어 조립, 팔만 교체, 맞지 않는 BON 거부/기존 상태 유지, 슬롯별 텍스처 해제/재연결, 클립 선택/재생, BON/메시 해제, 몬스터 전환.
- 검증 모드는 자체 테스트 경로로 실행하며 파일 선택창을 수동 클릭하는 검사는 포함하지 않습니다.

프로젝트 폴더에서 PowerShell 실행 예시:

```powershell
$resources = 'C:\Users\yumkl\OneDrive\바탕 화면\바우트 리소스'
$results = Join-Path $PWD 'verification'
node .\prepare-reference.cjs $resources $results
Start-Process .\bin\x64\Debug\ModelStudio.exe -ArgumentList "--verify `"$resources`" `"$results`"" -WindowStyle Hidden -Wait
Start-Process .\bin\x64\Debug\ModelStudio.exe -ArgumentList "--ui-verify `"$resources`" `"$results`"" -WindowStyle Hidden -Wait
```

`verification/verification.txt`, `interface-verification.txt`, 각 세트의 PNG에 결과가 저장됩니다.
